# つみき王国 (Tsumiki Oukoku / "Block Kingdom")

明るくやさしいローポリのファンタジー世界で、自由にブロックを積んで建物を作るブラウザ向けボクセル建築ゲームです。
バックエンド・サーバーは不要で、`npm run dev` だけでローカルに起動できます。UI はすべて日本語です。

これは **Phase 5 (長時間セッションの性能改善・動的な世界状態の永続化・操作/使いやすさの強化)** の実装です。既存の商用ボクセルゲームの素材・名称は一切使用していません。

## 必要環境

- Node.js 20 系以上 (npm 同梱)
- 最新の Chrome または Edge (デスクトップ)。タッチ操作はタッチスクリーン付きラップトップでも動作します。

## セットアップと起動

### コマンドプロンプトから起動する

1. エクスプローラーでプロジェクトフォルダーを開き、アドレスバーに `cmd` と入力して Enter を押します。
2. 初回だけ依存関係をインストールします。
3. 開発サーバーを起動します。

```bat
npm install
npm run dev -- --host 127.0.0.1 --port 5173
```

別の場所からコマンドプロンプトを開いた場合は、先にプロジェクトフォルダーへ移動してください。

```bat
cd /d "C:\path\to\shota_games"
npm install
npm run dev -- --host 127.0.0.1 --port 5173
```

起動後、ChromeまたはEdgeで `http://127.0.0.1:5173/` を開きます。サーバーを終了するときは、コマンドプロンプト上で `Ctrl+C` を押し、確認が表示された場合は `Y` を入力します。

### 起動バッチを使う

リポジトリ直下の **`start-game.bat`** をダブルクリックすると、必要に応じて初回の `npm install` を行い、ローカルサーバーを起動してブラウザーを開きます。

- 必要環境: Node.js 20以上
- URL: `http://127.0.0.1:5173/`
- 終了方法: バッチの画面で `Ctrl+C`
- ブラウザーを自動で開かずに起動: `start-game.bat --no-open`

従来の短いコマンドでも起動できます。

```bash
npm install       # 依存関係のインストール
npm run dev       # 開発サーバーを起動し、http://localhost:5173/ を表示
```

その他のスクリプト:

```bash
npm run typecheck  # TypeScript の型チェックのみ (tsc --noEmit)
npm test           # Vitest によるユニットテスト実行
npm run test:watch # ウォッチモードでテスト実行
npm run build      # 型チェック + 本番ビルド (dist/ に出力)
npm run preview    # ビルド済みファイルをローカルで確認
```

`npm run build` が通れば型チェック・本番バンドルの両方が成功していることを意味します。

## 遊び方の概要

1. タイトル画面で新しいワールドを作成します。名前は必須、シードは任意で、さらに **ゲームモード (クリエイティブ / サバイバル)** を選びます。既存ワールドを選択してロードすることもできます。
2. 初回のみ、ようこそ画面と基本操作ヘルプが表示されます (ポーズメニューからいつでも再表示可能)。
3. マウスクリックでポインターロックし、一人称/三人称視点を切り替えながら地形を歩き回れます。クリエイティブでは飛行モードも利用できます。
4. 左クリックでブロック破壊 (サバイバルでは狙った生物への攻撃も兼ねます)、右クリックで設置。クイックバー (画面下部) とインベントリからブロックを選べます。
5. クリエイティブでは、Undo/Redo (最大100件、セッション内) で建築を元に戻せます。
6. クリエイティブでは、範囲選択→コピー→貼り付けで建物の一部を素早く複製できます。90度回転・鏡像反転も可能で、名前を付けて「設計図ライブラリ」に保存し、別のワールドでも読み込んで使い回せます (建築メニュー [G])。
7. ワールドは自動保存され (IndexedDB)、タイトル画面からエクスポート/インポートも可能です。設計図ライブラリも同様にJSONファイルとして書き出し/読み込みができます。
8. サバイバルモードでは、資源を集めて [I] キーでクラフト画面を開き、道具・食料・回路パーツ・ベッド・家具などを作成します。昼夜サイクルがあり、夜や地下ではモンスターが出現します。
9. 地下遺跡には宝箱が眠っていることがあります。初めて開けるとシードと座標から決まるアイテムを1回だけ入手できます。ブロック設置・討伐・クラフト・発見などの進行状況は「探索の記録」画面 ([P] または一時停止メニュー) でいつでも確認できます。

## ゲームモード

| モード | 特徴 |
| --- | --- |
| クリエイティブ | 体力・空腹・資源制限なし。ダメージを受けず、全ブロックを無制限に設置/取得できる建築特化モード。 |
| サバイバル | 体力・空腹・資源収集・クラフト・落下ダメージ・モンスターとの戦闘・死亡復活がある挑戦モード。 |

ワールド作成時に選んだモードは保存データに記録され、後から変更することはできません (別モードで遊びたい場合は新しいワールドを作成してください)。旧バージョン (スキーマv1/v2) のセーブデータは自動的に現在のスキーマv3へ移行され、モードが無いデータは安全側のデフォルトである **クリエイティブ** として扱われます。

## サバイバルモードの仕組み

- **体力とお腹**: 画面左上にハート (体力) と肉アイコン (満腹度) を表示。お腹が減ると回復が止まり、さらに減り続けると体力が徐々に減少します。落下ダメージやモンスターの攻撃でも体力が減ります。体力が0になると死亡します。
- **資源収集**: ブロックを壊すと対応する資源がインベントリに入ります (例: 木の葉→植物繊維)。インベントリ内の個数はクイックバー上にも表示されます。
- **クラフト**: [I] キーでインベントリ/クラフト画面を開きます。木の板・棒・丸石・石レンガ・レンガ・ガラス・焼き肉・応急手当キット・石の剣・ベッド・スイッチ・導線・ランプ・宝箱・テーブル・椅子など、実用的な一連のレシピを用意しています (3x3配置ではなく、材料を集めてボタンを押すだけのシンプル方式)。材料が不足しているレシピは不足分が赤く表示され、何が足りないか一目で分かります。
- **昼夜サイクル**: 画面右上に時刻を表示。空の色・太陽/月光の明るさが時間とともに変化します。夜間や地下 (Y座標が低い暗い場所) ではモンスターが出現しやすくなります。
- **モンスター (5種)**: スライム、ゴブリン、コウモリ、ゴースト、ロックゴーレム。低ポリで視覚的に区別しやすく、プレイヤーを検知すると追跡・接触攻撃してきます。倒すと種類ごとの素材をドロップします。パフォーマンスのため同時出現数と生成間隔に上限があります。
- **友好的な動物 (4種)**: ひつじ、うし、にわとり、うさぎ。攻撃してこず、ゆっくりと徘徊します。攻撃して倒すと資源 (羊毛/生肉/革など) をドロップし、条件を満たすと近くの同種同士で繁殖することもあります。
- **死亡と復活**: 体力が0になると、その場に持ち物一式を落として死亡画面が表示されます。復活ボタンでワールドのスポーン地点 (またはベッドを使って設定した地点) に戻ります。死亡地点に戻ると落とした持ち物を自動的に回収できます。
- **回路**: スイッチ・導線・ランプ・ドアで簡単な電気回路を作れます。スイッチを [E] で切り替えると、隣接する導線を伝って電力が広がり (伝播範囲には上限があります)、ランプが点灯したり、繋がったドアが自動で開閉したりします。回路に繋がっていないドアは従来どおり手動での開閉のみです。回路の配置と状態はワールド保存に含まれます。

## 操作方法 (タッチスクリーン)

タッチ対応デバイスを検出すると、画面下部に自動でタッチ UI が表示されます (設定でオン/オフ切り替え可能)。設定画面でのオン/オフはプレイ中に即座に反映されます — オンにすればその場でタッチUIが生成され、オフにすれば破棄されます (Phase 5)。タッチ非対応デバイスでも、動作確認のために手動でオンにすることができます。

- 左下: 仮想ジョイスティック (移動)
- 右側ドラッグ: 視点操作
- 右下: 破壊ボタン / 設置ボタン / 使うボタン (ドア・スイッチ・ベッド・攻撃を兼ねる) / ジャンプ・飛行切り替えボタン

デスクトップのキーボード＋マウス操作は妥協せず、タッチはあくまで追加の入力手段として実装しています。

## Phase 1 で実装済みの範囲

- **地形**: シード指定可能な手続き生成地形。16×16 チャンク単位で読み込み/破棄され、プレイヤー周辺のみを描画 (ラップトップ想定の控えめな描画距離、チャンクの動的破棄でメモリを節約)。
- **ブロック**: 空気を除く40種類の設置可能ブロックを地形/木材/石材/特殊/回路/家具の6カテゴリーに分類。追加素材も組み込みやすいデータ駆動の定義構造 (`src/core/blocks.ts`)。
- **特殊パーツ**: 代表実装として階段・柵・ドア (開閉インタラクション付き) を用意。形状ごとのメッシュ生成 (`src/render/specialMeshes.ts`) を拡張すれば追加パーツを容易に追加可能。
- **カメラ**: 一人称/三人称をプレイ中にいつでも切り替え可能。
- **移動**: 地上歩行。クリエイティブでは自由飛行もトグルで切り替え可能。
- **建築操作**: グリッド単位の設置/破壊。クリエイティブではUndo/Redo (セッション内最大100件) と範囲選択→コピー→貼り付けも利用可能。
- **UI**: 画面下部のクイックバー、インベントリパネル、HUD (クロスヘア・ステータス表示)。
- **ワールド管理**: 名前+任意シード+モード選択での新規作成、一覧、リネーム、削除 (確認ダイアログあり)、ロード、自動保存 (IndexedDB)、ワールドファイルのエクスポート/インポート (JSON、スキーマバージョン付き)。
- **設定**: FOV、マウス感度、描画距離、画質 (低/中/高)、マスター/BGM/SFX 音量、主要キーのリバインド、カメラシェイクのオン/オフ (デフォルトはオフ)。
- **アバター**: ユーザーが指定した顔写真から、ブラウザ内で完結する処理のみで簡易なカラーパレット (肌色・髪色の近似) を抽出し、髪型・髪色・肌色・服の色を調整可能。UI 上で「本人そっくりの再現ではなく、簡略化されたキャラクターへの近似である」ことを明記 (写真は外部送信・保存されません)。
- **サウンド**: Web Audio API による軽量な手続き生成 SFX (設置/破壊/足音/UI操作/Undo/Redo/ダメージ/クラフト/生物のヒット・撃破/スイッチ・ドアほか) と環境アンビエント。著作権のある音源は一切未使用。
- **オンボーディング**: 初回ウェルカム画面と、いつでも開ける操作ヘルプ (サバイバルの遊び方を含む)。
- **アクセシビリティ/UX**: レスポンシブレイアウト、キーボードフォーカス対応、`prefers-reduced-motion` 配慮、破壊的操作 (ワールド削除等) の確認ダイアログ、エラー発生時のトースト通知 (無言の失敗を避ける)。
- **セーブデータ**: スキーマバージョン管理付きの JSON シリアライズ形式 (v1/v2→v3 の自動移行を含む)。
- **テスト**: 純粋ロジック (シード/ハッシュ、地形生成、チャンク、ブロック編集、Undo/Redo履歴、選択範囲、ワールド保存シリアライズと移行、設定の正規化、アバターパレット抽出、ゲームモード、インベントリ、クラフト、サバイバル、昼夜サイクル、回路伝播、簡易AI) に対する Vitest ユニットテスト。

## Phase 3 で追加された範囲 (バイオーム・地下生成・天候)

- **バイオーム**: ワールドシードと座標だけから決定論的に「草原・森林・砂漠・雪原・山地・海」の6種類を選択 (`src/core/biome.ts`)。広い領域単位でなめらかに遷移し、市松模様のような細かいノイズにはなりません。地表のブロック構成・地形の高さ・木の生え方・色合いがバイオームごとに変化します。
- **地下生成**: 地表の下には歩き回れる洞窟が自然に広がり (`src/core/underground.ts`)、深さとバイオームに応じて金属パネル・黄金ブロック・光晶石が鉱脈として埋まっています。低地には地下水だまりが、地表の低地には海 (水没した地形) が生成されます。ごくまれに小さな地下遺跡が生成され、レアな鉱石の目印になります。チャンクの読み込み順序に関わらず同じシードなら同じ地形になり、チャンクの境目 (シーム) で洞窟や鉱脈が途切れないよう座標ベースで生成しています。
- **水**: 水/地下水/海のブロックは半透明で描画され、衝突判定を持たない (壁のように塞がれない) ため、泳いで通り抜けられます。水中では移動と落下がゆっくりになる簡易的な水泳挙動を実装しています (本格的な流体シミュレーションは意図的に対象外)。
- **天候**: シードとゲーム内経過時間から決定論的に「晴れ・雨・雪」が移り変わります (`src/core/weather.ts`)。雪原・山地では雪、砂漠では雨が降らず常に晴れ、それ以外のバイオームでは雨になります。雨/雪はラップトップでも軽い、上限付きのパーティクル (最大260個、プレイヤー追従、意図的な再利用でメモリ確保なし) で表現し (`src/render/weatherEffects.ts`)、空の色や光の強さをわずかに変化させますが、建築の視認性を著しく損なわない範囲に制限しています。
- **環境音**: 雨・風・洞窟内の手続き生成アンビエントを追加 (既存のマスター/BGM音量設定に従う)。ループ音源は起動時に一度だけ生成し、フェード制御のみで音量を変化させるため、継続的な音声生成によるノイズ/GC負荷はありません。
- **HUD/オンボーディング**: 画面右上に現在のバイオーム名と天候 (アイコン+日本語ラベル) を表示。ウェルカム画面と操作ヘルプに、バイオーム・洞窟・鉱脈・地下水/海・地下遺跡・天候の説明を追加しました。
- **セーブデータ互換性**: `terrainGeneratorVersion` をセーブデータに追加し、Phase 1/2 時代に生成されたワールドは既存の地形生成ロジックのまま (地形が変化しない) 動作します。新規ワールドのみ Phase 3 の生成ロジックを使用します。既存の編集済みブロックは引き続き自動生成より優先されます。

## Phase 4 で追加された範囲 (建築補助の強化・探索/進行要素)

### A. 高度な建築ツール (クリエイティブ専用)

- **クリップボードの回転・鏡像反転**: コピーした選択範囲を、Y軸周りに90度単位で時計回り/反時計回りに回転、またはX軸/Z軸方向に鏡像反転できます (`src/core/selection.ts`)。階段・ドア・スイッチなどが持つ向き (facing) も、セルの座標変換と矛盾なく一緒に変換されます。
- **設計図ライブラリ**: 現在のクリップボード内容に名前を付けて保存し、一覧から読み込み・リネーム・削除ができます (`src/core/blueprint.ts`)。保存先はブラウザのIndexedDBで、ワールドとは独立して管理されるため、別のワールドでも同じ設計図を使い回せます。単体のJSONファイルとしてエクスポート/インポートも可能で、インポート時は寸法・最大体積・ブロックID・向き・名前の長さなどを厳密に検証し、不正なデータは読み込みを拒否します。IndexedDBのスキーマは既存のワールド/設定/アバターのストアを維持したまま加算的にアップグレードされます (バージョン1→2、既存データは削除されません)。
- **建築メニュー UI**: [G] キーまたは一時停止メニューから開ける日本語UIで、選択/コピー/回転/鏡像反転/貼り付け/設計図ライブラリの操作をまとめて行えます (`src/ui/buildMenu.ts`)。サバイバルモードでは操作ボタンが無効化され、明示的な警告バナーが表示されます。
- **選択範囲の視認性向上**: 範囲選択の開始点/終了点それぞれでトースト通知を表示し、確定前でも視点を動かすと選択プレビュー (黄色いワイヤーフレーム) がリアルタイムに更新されるため、2点方式の選択操作が分かりやすくなっています。

### B. 探索・進行要素

- **宝箱・家具ブロック**: 新たに宝箱・テーブル・椅子を追加 (合計40種類の上限内)。宝箱は開閉アニメーション付きの専用メッシュを持ち、クラフトも可能です (`src/core/blocks.ts`, `src/render/specialMeshes.ts`, `src/core/crafting.ts`)。
- **地下遺跡の宝箱**: Phase 4以降に作成した地形ジェネレーターv3のワールドでは、地下遺跡にシードと座標から決定論的に宝箱が配置されます (`src/core/underground.ts`)。Phase 3の地形ジェネレーターv2ワールドは、遺跡中央の黄金ブロックを含む従来地形を維持します。未開封の生成宝箱を初めて開けると、シード+座標から決まる内容のアイテムを1回だけ入手でき、視覚的に開いた状態になります。この「開封済み」の記録はワールド保存に永続化され、ブロックを壊して置き直しても再度は入手できません。
- **実績・進行状況**: 「はじめてのブロック設置」「ブロック設置100個」「はじめての洞窟発見」「全6バイオーム踏破」「はじめての遺跡の宝箱」「はじめてのクラフト」「はじめての討伐」「回路の初点灯」など、8種類の代表的な実績を用意 (`src/core/achievements.ts`)。データ駆動のレジストリ形式で、条件を満たすと自動的に解除されトースト通知が表示されます。進行状況はセーブデータに保存され、旧バージョンのセーブも安全に移行されます。
- **探索の記録画面**: [P] キーまたは一時停止メニューから開ける日本語UIで、発見済みバイオーム・開封した宝箱の数・設置ブロック数・クラフト数・討伐数・解除済み実績の一覧を確認できます (`src/ui/achievementsPanel.ts`)。

### C. 互換性・品質

- **セーブデータ**: スキーマは引き続きv2のまま、新規フィールド (`progress`, `lootedTreasures`) を追加し、旧バージョンのセーブデータは自動的にデフォルト値 (実績なし・宝箱未開封) で補完されます。既存の地形・編集内容・死亡ドロップなどの検証ロジックは変更していません。
- **回帰防止**: 安全なスポーン地点、水泳、天候/環境音のライフサイクル、死亡ドロップの永続化とマージ、破壊されたベッドの挙動、サバイバルでの飛行禁止、クリエイティブ専用のUndo/Redo/範囲貼り付け、設定/アバターの永続化、イベントの後始末、先読みチャンク描画など、既存の挙動はすべて維持されています。
- **テスト**: 新規モジュール (クリップボード変換, 設計図の検証/シリアライズ, 宝箱抽選, 実績判定, セーブデータ移行) に対する純粋関数のユニットテストを追加しています。

## Phase 5 で追加された範囲 (長時間セッションの性能改善・動的な世界状態の永続化・操作/使いやすさの強化)

### A. 動的な世界状態の永続化

- **生存生物の永続化**: ワールドを閉じたとき (自動保存/タイトルへ戻る/タブ非表示化) に、生存中の全生物のスナップショット (種類・安定ID・座標・向き・現在HP/AI状態・徘徊/追跡タイマー・攻撃クールダウン・繁殖クールダウン) を保存し、次にワールドを開いたときに一度だけ復元します (`src/game/entitySystem.ts` の `restoreEntities`/`getSnapshot`)。復元は通常のスポーン処理より先に行われるため二重出現せず、復元後に発行されるIDは既存IDと衝突しないようカウンターを進め、上限到達時は安全な範囲へ循環して使用中IDを避けます (`src/core/entityAI.ts`, `src/game/entitySystem.ts`)。復元された生物も既存の出現数上限 (敵対8体/友好6体) の対象になります。旧セーブ (entitiesフィールドが無い) は空の生物リストへ移行され、通常通りその場でスポーンし直されます。保存データは既知の生物種類・有限で妥当な範囲の座標・種類ごとの最大HP以内・有効なAI状態 (「dead」は保存対象外)・ID重複なし・保存数上限 (64体) を厳格に検証し、壊れた/悪意あるインポートを拒否します (`src/core/save.ts` の `validateEntities`)。
- **死亡ドロップのリスト化**: Phase 4までの「死亡ドロップは常に1個 (新しい死亡で前回の中身を自動マージ)」から、複数の独立した回収可能なドロップを最大10件まで保持するリストに変更しました (`src/core/deathDrops.ts`)。各ドロップは安定したID・座標・持ち物・生成時刻を持ち、シーン上にそれぞれ専用のマーカーが表示され、プレイヤーに最も近い回収可能なドロップから1つずつ自動回収されます。上限を超えて死亡した場合のみ、最も古いドロップの中身を次に古いドロップへ合流させ (アイテムは失われず、件数だけが減る)、その旨をトースト通知します。旧形式の単一 `deathDrop` を持つセーブは、中身を失わずに1件のリストへ自動移行します。インポートされたリストは、上限件数・ID重複なし・インベントリの中身 (既知のアイテムキー/非負整数) を厳格に検証します。

### B. ワールド/チャンクの性能改善

- **チャンク生成キュー**: Phase 3までは、プレイヤーが動くたびに描画距離内の全チャンクを同期的に生成しており、描画距離が大きいほど1フレームに大きな処理のかたまりが発生してカクつきの原因になっていました。Phase 5では、プレイヤーに近い順に並べた候補リストから「1フレームあたり生成2件・メッシュ構築2件」までという予算付きのキューで処理を分散させます (`src/core/chunkQueue.ts`, `src/render/worldRenderer.ts`)。境界面の確認には未ロードチャンクを生成しない参照を使い、隣接チャンクのロード時に双方を再メッシュするため、メッシュ構築が生成予算を迂回しません。プレイヤーが現在いるチャンクだけは、衝突判定/レイキャストに必要なため同期的に確保・描画され、保存済みの編集内容は常に生成データより優先されます。
- **Webワーカーを採用しなかった理由**: プレイヤーの移動衝突判定 (`player.ts`)・レイキャスト (`raycast.ts`)・生物AIの足場サンプリング (`entityAI.ts`/`entitySystem.ts`) は、いずれも `World.isSolid`/`getBlockId`/`findHighestSolidY` を同期的に呼び出す設計です。チャンク生成をワーカーへ移すには、これら全ての呼び出し元を非同期 (postMessageの往復) へ書き換える必要があり、既存の同期的なゲームプレイ挙動を壊すリスクが高いと判断しました。そのため、本フェーズでは「メインスレッド上の予算付き優先度キュー」という、より安全で確実な代替策を採用しています (詳細な理由は `src/render/worldRenderer.ts` の冒頭コメントを参照)。
- **メッシュ再構築の間引き**: 毎フレーム全ロード済みチャンクを走査していた従来の実装をやめ、優先度キューが指し示す「新規チャンク」「dirtyフラグが立っているチャンク」だけを、近い順・予算付きで処理します。現在チャンクは常に即座に可視化されます。
- **デバッグHUD**: 一時停止/設定画面のチェックボックスで切り替え可能な軽量な診断オーバーレイ (`src/ui/debugHud.ts`) を追加しました。FPS・ロード済みチャンク数・キュー待ちチャンク数・生存生物数・描画コール数/三角形数を表示します。既定は非表示で、設定はワールドをまたいで永続化されます。オフ時はループ内の分岐1つが増えるだけで、統計収集やDOM更新は一切行われません。

### C. 操作/使いやすさの強化

- **タッチ操作のライブ切り替え**: 設定画面での「タッチ操作UIを表示する」のオン/オフが、プレイ中に即座に反映されます。オンにすればその場でタッチUIを生成し、オフにすれば `window` リスナーを含めて確実に破棄します。再度オンにしても、リスナーが重複することはありません (`Game.enableTouchControls`/`disableTouchControls`)。
- **はじめてのチェックリスト**: 新しいワールドを開いた直後に、画面右上へコンパクトな非モーダルのチェックリストを表示します (`src/ui/tutorialChecklist.ts`)。「移動/視点操作」「設置/破壊」「インベントリ/クラフトを開く」「一人称/三人称の切り替え」「(モードに応じて) 飛行切り替え、またはサバイバルの体力/お腹表示の確認」の各項目が、対応する操作を行うたびに自動でチェックされます。閉じる/全項目完了した状態はワールドIDごとに永続化され (`src/core/storage.ts` の `TutorialChecklistState`)、同じワールドを再度開いても熟練者を繰り返し邪魔しません。一時停止メニューの「はじめてのチェックリストを表示」からいつでも再度開けます。

### D. 互換性・セーブスキーマ

- **セーブスキーマ v3**: Phase 5では実質的な構造変更 (`deathDrop`→`deathDrops`、`entities`の新規追加) を行うため `SAVE_SCHEMA_VERSION` を3へ引き上げ、`validateAndMigrateWorldSave` に実際の移行ロジックを実装しました (`src/core/save.ts`)。将来のバージョンで保存されたデータ (`version` がサポート範囲より大きい) は、これまで通りサイレントに受け入れず例外を投げます。
- **Phase 1〜4の互換性**: 旧地形ジェネレーターバージョン、安全な陸地スポーン、水/天候、破壊されたベッドの挙動、サバイバルでの飛行禁止、クリエイティブ専用の複製系ツール (Undo/Redo・範囲貼り付け・設計図)、設計図ライブラリのIndexedDB移行、生成遺跡宝箱の一回限り付与、実績/進行状況、設定/アバターの永続化、イベントリスナー/オーディオの後始末は、すべてそのまま維持しています。

## 既知の制限事項

- 範囲選択は「1回目のキー入力で開始点、2回目で終了点」の2ステップ方式です (ドラッグ選択は未実装)。視点を動かすと選択範囲のプレビューがリアルタイムに更新されるため、確定前に範囲を確認できます。
- 階段・柵・ドア・宝箱・テーブル・椅子などは代表的な簡易ジオメトリで実装されています (蝶番アニメーション等は簡略化)。
- レイキャストによるブロック照準は、視点モードに関わらずプレイヤーの向き基準で計算しています (三人称カメラの画角そのものではありません)。
- `src/core/storage.ts` の IndexedDB 永続化は実ブラウザでのみ検証しており、Vitest の対象外です (Node環境にIndexedDB実装が無いため)。設計図ライブラリのIndexedDBスキーマはワールド/設定/アバターと共存する形で追加されており (バージョン2への加算的アップグレード)、既存データを削除・破壊しません。
- 大きな範囲のコピー/貼り付け・設計図の保存/読み込みにはサイズ上限があり、超過時はエラー通知を表示します。
- 設計図ライブラリはブラウザのIndexedDBにのみ保存され、ワールドファイルとは別に管理されます (ワールドのエクスポート/インポートには含まれません)。設計図単体でのJSONエクスポート/インポートには対応しています。
- クリップボードの回転/鏡像反転・設計図の貼り付けは、資源の無限増殖を防ぐためクリエイティブモード専用です。サバイバルモードで操作しようとすると、その旨のエラー通知が表示されます。
- 「ブロック設置100個」実績は、手動設置に加えてクリエイティブの範囲貼り付け/設計図で実際に配置・置換された非空気ブロックもカウントします。
- 地下遺跡の宝箱は、シードと座標から決まる内容を初回開封時にのみ1回だけ付与します。この判定は「生成された遺跡の座標かどうか」という座標ベースの条件と、「その座標で既に開封済みかどうか」という永続化された記録の組み合わせによって、同じ座標でブロックを壊して置き直しても再度報酬を得ることはできません。ただし、未開封の生成宝箱を一度壊してから同じ座標にプレイヤーが新しく作成した宝箱を置いた場合、その新しい宝箱を開けると (座標が一致するため) 1回だけ報酬が付与される可能性があります (それ以降は再取得できません)。プレイヤーが生成宝箱ではない座標に自分で設置した宝箱には、報酬は一切付与されません。
- 実績・進行状況 (バイオーム発見、洞窟発見、宝箱開封数、設置ブロック数、クラフト数、討伐数、回路点灯) はワールドのセーブデータに保存されます。旧バージョンのセーブデータを読み込んだ場合は、これらの値はすべて0から自動的に補完されます。
- モンスター・動物は生存中の個体だけがワールド保存の対象です (Phase 5)。ワールドを閉じた時点で生きていた個体は次に開いたときに一度だけ復元されますが、保存できる数には上限 (64体) があり、悪意ある/壊れたインポートデータは種類・座標範囲・HP・状態を厳格に検証したうえで拒否されます。倒した個体が「消えたまま残る」ことはありません。
- 死亡時のドロップは、死亡地点ごとに個別の回収可能な荷物として最大10件まで保持されます (Phase 5)。上限を超えて死亡した場合のみ、最も古いドロップの中身が次に古いドロップへ自動的に合流します (アイテムは失われません)。個別アイテムがブロックのように地面へ散らばる表現ではありません。
- チャンク生成/メッシュ構築は「1フレームあたり生成2件・メッシュ構築2件」までの予算付きキューで分散処理されます (Phase 5)。現在位置のチャンクだけは操作に必要なため予算外で同期確保されますが、メッシュ境界確認から暗黙的に隣接チャンクが生成されることはありません。
- チャンク生成にはWebワーカーを採用していません (Phase 5)。プレイヤーの衝突判定・レイキャスト・生物AIの足場サンプリングが同期的なワールドAPIに依存しているため、より安全な「メインスレッド上の予算付き優先度キュー」で性能改善を行っています。
- デバッグHUD (FPS/チャンク数/生物数など) は概算値です。特に描画コール数/三角形数は直前フレームの `renderer.info` の値であり、厳密なリアルタイム値ではありません。
- 「はじめてのチェックリスト」はUIの表示状態のみをワールドIDごとに永続化するもので、ワールド本体のセーブデータ (エクスポート/インポート対象のJSON) には含まれません。
- 水中の物理は簡易的な浮力/水泳挙動であり、本格的な流体シミュレーションではありません。高速落下中に着水した直後は、水中判定が有効になるまでの1フレーム分だけ落下ダメージ判定が残る可能性があります (通常のプレイでは体感できない程度の簡略化です)。
- 天候の視覚効果はラップトップ向けに上限付きパーティクル (最大260個) で表現しており、降雨/降雪の密度や見た目は簡略化されています。
- Phase 1/2 で生成済みのワールドは `terrainGeneratorVersion` により従来の地形生成ロジックのまま維持され、バイオーム・洞窟・地下水・地下遺跡は再生成されません (新規ワールドでのみ Phase 3 の地形が生成されます)。地下遺跡の宝箱も、Phase 3以降の生成ロジックを使うワールドにのみ配置されます。
- Undo/Redo と範囲貼り付けは、資源の無限増殖を防ぐためクリエイティブモード専用です。
- 回路の電力伝播は隣接ブロックを辿るシンプルな幅優先探索で、対角線や特殊な論理ゲート (AND/OR等) は扱いません。
